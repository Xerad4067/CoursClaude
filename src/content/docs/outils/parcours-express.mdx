Objectif : arriver à ton choix d'option (vers janvier 2027) avec de **vraies bases de développement**, sans t'épuiser. Base indicative : **6 à 7 h par semaine**, découpées en séances de 15 min à 2 h. Ce cours **complète** ton BTS, il ne le remplace pas.

## Ton cours de Python a déjà commencé ? Prends la voie rapide

Ton école t'a lancé dans Python avant que tu aies fini Lua. Pas de panique : Lua et Python se ressemblent beaucoup, et le cours utilise ça.
- **Dès que tu as fait B1 à B4** (variables, conditions, boucles) : passe à [D1 · Python : premiers pas](/parcours-d/d1-python-premiers-pas/) (2 h) : installation de Python sur tes deux machines, puis ce que tu connais déjà, écrit en Python.
- Pour t'entraîner en parallèle de ton cours : la [salle d'entraînement Python](/entrainement/) (séries d'exercices testés par thème).
- Le planning ci-dessous place **D1 à D3 dès la semaine 4** pour cette raison. Si ton prof va plus vite, avance D2 : le parcours B n'a pas besoin d'être terminé pour comprendre D1 et D2.

Ce planning est **tendu mais réaliste** (environ 65 h de contenu en 12 semaines, hors salle d'entraînement). Si tu prends du retard, l'ordre de sacrifice est : d'abord le web (D8, D9), puis C6, puis les séries 🔴 de la salle d'entraînement. **POO et SQL passent avant** : ce sont elles qui comptent pour SLAM. Les parcours E et F s'ajoutent quand ton accès Nanos World s'ouvre.

## Jalons (un résultat visible toutes les deux semaines)

- **19 oct.** : deux machines prêtes, dépôt GitHub synchronisé, fiche de personnage et ticket de caisse en Lua.
- **2 nov.** : jeu de devinettes jouable dans le terminal, calculateur de salaire, et tes premiers programmes Python (D1) qui font la même chose que tes programmes Lua.
- **16 nov.** : mini-inventaire, annuaire des métiers en modules, mini boutique (parcours B terminé).
- **30 nov.** : un bug réparé avec la méthode du module C2, un code refactorisé et testé (C3).
- **14 déc.** : un conflit Git résolu, une Pull Request relue (C5, C6), ta première classe Python (D4).
- **21 déc.** : une petite base SQLite interrogée avec des jointures (D6, D7).
- **28 déc.** : une petite application « boutique » (classes, base SQLite, page web : D10) ; tu sais expliquer variables, fonctions, POO, SQL et Git avec **tes propres projets** sur GitHub.

## Semaine chargée ? Le rythme minimal

<Encadre type="retenir">
**3 séances de 30 minutes par semaine** suffisent à garder le contact. Ordre de priorité : A en entier → B1 à B6 → D1 et D2 (Python, si ton cours en a besoin) → la partie Git du parcours C → POO et SQL du parcours D. Une semaine à zéro ne casse rien : reprends simplement à ta « prochaine action ».
</Encadre>

## Quand ton accès Nanos World s'ouvre

Entrelace **deux séances de scripts (E) pour une séance de mapping (F)**, en gardant au moins la moitié de ton temps sur A-D jusqu'au 1er janvier.
