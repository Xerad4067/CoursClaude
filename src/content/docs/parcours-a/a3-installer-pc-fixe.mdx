**Pourquoi c'est utile ?** Le PC fixe est ta machine **principale** : c'est elle qui lancera le jeu et Unreal Engine. Refaire l'installation **seul**, sans relire chaque explication, prouve que tu as compris (et c'est exactement ce qu'on te demandera en entreprise sur un nouveau poste).

## Étape 1 · État des lieux et installations (20 min)

Lance les mêmes vérifications qu'au module A2 :

```powershell
winget --version
code --version
git --version
lua -v
node --version
```

Tu as peut-être déjà VS Code sur cette machine : dans ce cas, garde-le. Installe ce qui manque avec les mêmes commandes qu'au [module A2](/parcours-a/a2-installer-portable/) (Node.js est facultatif ici : utile seulement si tu veux lancer le site du cours sur le PC fixe).

Puis applique la **même configuration Git**, avec **la même identité** que sur le portable :

```powershell
git config --global core.editor "code --wait"
git config --global init.defaultBranch main
git config --global core.autocrlf true
git config --global user.name "TonPseudo"
git config --global user.email "ID+PSEUDO@users.noreply.github.com"
```

<Encadre type="piege">
Si l'identité diffère entre les deux machines (faute dans l'adresse), GitHub affichera tes commits comme venant de deux personnes différentes. Copie-colle exactement la même adresse.
</Encadre>

<FinEtape id="A3-e1" titre="PC fixe installé" victoire="les cinq commandes de vérification répondent sur le PC fixe." prochaine="retrouver tes réglages VS Code avec Settings Sync (étape 2)." />

## Étape 2 · Settings Sync : la magie (10 min)

Dans VS Code : roue dentée → **Backup and Sync Settings...** → **Sign in** → **GitHub**, avec **le même compte** que sur le portable. Après quelques secondes, tes extensions et réglages arrivent tout seuls. Vérifie :

```powershell
code --list-extensions
```

Tu dois retrouver la même liste que sur le portable.

<FinEtape id="A3-e2" titre="Settings Sync sur le PC fixe" victoire="VS Code est identique sur tes deux machines sans rien réinstaller à la main." prochaine="découvrir ce qui viendra plus tard sur le PC fixe (étape 3)." />

## Étape 3 · Ce qui attendra ton accès Nanos World (15 min)

Ne l'installe **pas** maintenant : lis seulement, pour savoir à quoi t'attendre.

| Outil | Pourquoi plus tard | Ce qu'il faut savoir |
|---|---|---|
| Steam + Nanos World | Accès en *Closed Testing* | Clé Steam reçue après sélection, ou playtest public ([Plan B](/outils/plan-b-nanos-world/)) |
| Serveur dédié | Parcours E | Très léger : peut aussi tourner sur le portable d'après la doc |
| Epic Games Launcher + **Unreal Engine 5.7** | Parcours F | Version exigée par la doc Nanos World au 06/10/2026 : **5.7.X** (à revérifier avant d'installer) |
| Windows SDK | Parcours F | Nécessaire pour « cooker » des assets |
| Blender | Optionnel | Petits objets 3D |

<Encadre type="retenir" titre="📌 16 Go de RAM et Unreal">
Epic recommande **32 Go de RAM** pour Unreal Engine 5.7 ; ton PC fixe en a 16. C'est suffisant pour de **petites maps** si tu fermes navigateur, Discord et jeu pendant le mapping, baisses la qualité de l'éditeur, laisses Windows gérer le fichier d'échange sur un SSD et sauvegardes souvent. Tout est détaillé dans le [tutoriel, section 15](/installer/tutoriel/#15-unreal-engine-57-avec-16-go-de-ram).
</Encadre>

<Exercice id="A3-ex05" titre="Débogage : deux identités" niveau="jaune" type="debug">
Sur GitHub, une partie de tes commits affiche ta photo, l'autre une silhouette grise. `git config --global user.email` affiche `12345+leo@users.noreply.github.com` sur le portable et `12345+Leo@users.noreply.github.con` sur le PC fixe. Trouve l'erreur et corrige.

<div slot="indice1">Compare les deux adresses caractère par caractère.</div>
<div slot="indice2">Regarde la toute fin de l'adresse.</div>
<div slot="indice3">`.con` au lieu de `.com`.</div>
<div slot="solution">

Les prochains commits seront bien reliés à ton compte.

<Exercice id="A3-ex07" titre="Lecture : pourquoi pas sur le portable ?" niveau="jaune" type="lecture">
Un ami te conseille d'installer Unreal sur ton portable « pour faire du mapping en cours ». Avec les informations du cours, explique en trois arguments pourquoi c'est une mauvaise idée.

<div slot="indice1">Pense à la carte graphique, au stockage et à la mémoire.</div>
<div slot="indice2">Epic recommande 32 Go de RAM et une carte DirectX 12.</div>
<div slot="indice3">Le portable a un GPU intégré basse consommation et 512 Go partagés avec tout le reste.</div>
<div slot="solution">

1. **Carte graphique** : intégrée et basse consommation, alors qu'Unreal est fait pour des cartes dédiées.
2. **Stockage** : Unreal + caches + projets prennent des dizaines de Go sur un SSD de 512 Go.
3. **Rôle de la machine** : le portable doit rester léger et rapide pour coder ; le PC fixe (RTX 5060 Ti) est fait pour ça.
</div>
</Exercice>

<Exercice id="A3-ex08" titre="Défi : préparer le PC fixe pour Unreal" niveau="rouge">
Sans rien installer, vérifie l'espace libre sur le disque de ton PC fixe et la quantité de mémoire. Conclus : as-tu assez de place pour Unreal Engine (plusieurs dizaines de Go) et tes projets ?

<div slot="indice1">Deux commandes en lecture seule de la [Checklist](/installer/checklist/).</div>
<div slot="indice2">L'une donne l'espace des disques, l'autre les informations du système.</div>
<div slot="indice3">`Get-PSDrive C` et `systeminfo` (ligne « Mémoire physique totale »).</div>
<div slot="solution">

```powershell
Get-PSDrive C
systeminfo
```
Lis la colonne `Free (GB)` et la ligne de mémoire physique. Si le disque C: a moins d'une centaine de Go libres, prévois un autre disque (SSD de préférence) pour Unreal et tes projets. Note ta conclusion dans ton journal : tu la retrouveras au parcours F.
</div>
</Exercice>

## Récapitulatif

- Même procédure que le portable, en **autonomie** : vérifier → installer → rouvrir → revérifier.
- **Même identité Git** sur les deux machines, Settings Sync pour VS Code.
- Unreal Engine (5.7.X selon la doc), Steam et Nanos World : **plus tard**, sur le PC fixe uniquement.

## Je suis bloqué, que faire ?

Reprends le [module A2](/parcours-a/a2-installer-portable/) étape par étape, puis [Dépannage](/outils/depannage/). Si une commande marche sur le portable mais pas sur le PC fixe, compare les versions (`winget --version`, version de Windows avec `systeminfo`).
