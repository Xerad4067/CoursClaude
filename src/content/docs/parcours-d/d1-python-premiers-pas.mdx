## Étape 1 · Installer Python et lancer un fichier (20 min)

Cette étape se fait sur **tes deux machines** (portable 💻 et PC fixe 🖥️) : 5 minutes chacune. Si ton cours de BTS t'a déjà fait installer Python, commence par vérifier (point 1).

1. Ouvre le terminal (voir [le tutoriel d'installation](/installer/tutoriel/)) et tape :

```powershell
python --version
py --version
```

Si tu vois `Python 3.13.x` (ou un autre `Python 3.x`), Python est déjà là : passe au point 3. Ce cours est **testé avec Python 3.13** ; une autre version 3.x récente suffit pour la plupart des exemples, mais en cas de doute installe la 3.13.

2. Sinon, installe-le avec `winget`. L'identifiant `Python.Python.3.13` est **vérifié** dans le dépôt officiel des manifestes `winget` (`microsoft/winget-pkgs`, version 3.13.15 vue le 06/10/2026), mais la commande est **non testée sur Windows** :

```powershell
winget install -e --id Python.Python.3.13
```

Puis **ferme et rouvre le terminal** (Windows relit la liste des programmes à l'ouverture) et relance `python --version`. Le manifeste déclare les commandes `python` et `py` : `py` est le « lanceur » de Python pour Windows (il retrouve les versions installées).

3. Dans VS Code, installe l'extension **Python** (identifiant `ms-python.python`, éditeur Microsoft : identifiant vérifié dans la documentation de VS Code). Elle apporte la coloration, l'autocomplétion et le bouton d'exécution ; **elle n'installe pas Python lui-même**. En ligne de commande (non testé sur Windows) :

```powershell
code --install-extension ms-python.python
```

4. Dans ton dépôt d'apprentissage, crée le dossier du module et le fichier :

```powershell
cd ~\Dev\mon-apprentissage
mkdir python
cd python
code .
```

Dans VS Code, crée le fichier `bonjour.py` (le nom **finit par `.py`**) :

```python title="python/bonjour.py"
# Mon premier programme Python
print("Bonjour depuis Python !")
```

5. Lance-le depuis le terminal intégré de VS Code (menu **Terminal → Nouveau terminal**) :

```powershell
python bonjour.py
```

Résultat attendu : `Bonjour depuis Python !`. Tu peux aussi cliquer sur le bouton ▶ **Run Python File** en haut à droite de l'éditeur (d'après la documentation de VS Code, il lance `python bonjour.py` sous Windows). Si VS Code te demande de choisir un « interpréteur », prends celui de Python 3.13 (commande **Python: Select Interpreter**).

Voici tes premiers repères, côte à côte :

| | En Lua | En Python |
|---|---|---|
| Lancer un fichier | `lua bonjour.lua` | `python bonjour.py` |
| Commentaire | `-- texte` | `# texte` |
| Afficher | `print("Salut")` | `print("Salut")` |
| Créer une variable | `local x = 5` | `x = 5` (pas de `local`) |
| Fin d'un bloc | `end` | rien : c'est l'**indentation** (étape 5) |

## Étape 2 · Variables et types (20 min)

En Python, tu crées une variable en lui donnant une valeur : `nom = "Sam"`. Pas de `local`, pas de mot-clé. Ce que tu écris est **à la fois** la création et l'affectation.

```python title="d1/variables.py"
nom = "Sam"          # str : du texte
argent = 1500        # int : un nombre entier
taux = 1.5           # float : un nombre à virgule (avec un POINT)
permis = True        # bool : True ou False, avec une MAJUSCULE
vehicule = None      # None : « rien », l'équivalent de nil

argent = argent + 200            # on change le contenu : même idée qu'en Lua
print(nom, argent, taux, permis, vehicule)   # Sam 1700 1.5 True None
print(type(argent))                          # <class 'int'>
```

Les types se correspondent presque un pour un :

| En Lua | En Python | Exemple |
|---|---|---|
| `number` (entier) | `int` | `1500` |
| `number` (décimal) | `float` | `3.5` |
| `string` | `str` | `"Sam"` |
| `boolean` : `true` / `false` | `bool` : `True` / `False` | `True` |
| `nil` | `None` (son type s'appelle `NoneType`) | `None` |
| `table` | `list`, `dict`, `tuple`, `set` (module [D2](/parcours-d/d2-python-structures/)) | `[1, 2]` |

`type(valeur)` donne le type, comme en Lua. Les deux langages ont des variables **dynamiques** : une même variable peut contenir un nombre puis du texte.

<Encadre type="piege" titre="⚠️ True, False, None : la majuscule compte">
En Lua, `true`, `false` et `nil` sont en minuscules. En Python, ce sont `True`, `False` et `None`. Si tu écris `permis = true`, Python répond :

```text
NameError: name 'true' is not defined. Did you mean: 'True'?
```

Et `nil` n'existe pas du tout : `NameError: name 'nil' is not defined`.
</Encadre>

<Encadre type="retenir" titre="Une faute de frappe ne passe plus inaperçue">
En Lua, `print(argnet)` affichait `nil` sans rien dire (module B1) : un bug **silencieux**. En Python, la même faute plante tout de suite et propose même la correction :

```text
NameError: name 'argnet' is not defined. Did you mean: 'argent'?
```

C'est moins confortable sur le moment, mais plus honnête : tu trouves le bug plus vite.
</Encadre>

### Bien nommer en Python

Le cours Lua utilisait le *camelCase* (`prixTotal`). En Python, la convention officielle (PEP 8) est le ***snake_case*** : minuscules et tirets bas, `prix_total`, `liste_courses`. Comme en Lua : pas d'espace, ne commence pas par un chiffre, et dans ce cours **pas d'accents dans les noms** (`metier`, pas `métier`) pour éviter les soucis entre machines.

## Étape 3 · Afficher, f-strings et input (20 min)

**`print`** ressemble à celui de Lua, avec une différence : quand tu lui donnes plusieurs valeurs, il les sépare par une **espace** (Lua : une **tabulation**). Et tu peux choisir la séparation avec `sep` et la fin de ligne avec `end` :

```python title="d1/print.py"
print("Sam", 1500, "taxi")             # Sam 1500 taxi
print("Sam", 1500, "taxi", sep=" | ")  # Sam | 1500 | taxi
print("Chargement", end="...")         # pas de retour à la ligne
print("terminé")                       # Chargement...terminé
```

Pour **coller du texte avec des variables**, Python n'utilise pas `..` mais les **f-strings** (*formatted string literals*, « chaînes formatées »). Tu écris un `f` juste avant le guillemet, et tout ce qui est entre accolades est calculé :

```python title="d1/fstring.py"
nom = "Sam"
argent = 1500
prix = 3.5
print(f"{nom} a {argent} €")            # Sam a 1500 €
print(f"Prix : {prix:.2f} €")           # Prix : 3.50 € (2 chiffres après la virgule)
print(f"Double : {argent * 2}")         # on peut calculer dans les accolades
print(f"Avec séparateur : {argent:,}")  # Avec séparateur : 1,500
```

Après les deux-points, le **format** : `.2f` (deux décimales) joue le rôle du `%.2f` de `string.format`.

| But | En Lua | En Python |
|---|---|---|
| Coller du texte et des valeurs | `"Sam a " .. argent .. " €"` | `f"Sam a {argent} €"` |
| Mettre en forme un nombre | `string.format("%.2f", x)` | `f"{x:.2f}"` |
| Longueur d'un texte | `#nom` | `len(nom)` |
| Majuscules | `string.upper(nom)` | `nom.upper()` |
| Répéter un texte | `string.rep("=", 5)` | `"=" * 5` |
| Texte → nombre | `tonumber("250")` (`nil` si impossible) | `int("250")` ou `float("2.5")` (**erreur** si impossible) |
| Nombre → texte | `tostring(42)` | `str(42)` |
| Lire le clavier | `io.read()` | `input("Question : ")` |

### Lire le clavier avec input

```python title="d1/saisie.py"
pseudo = input("Ton pseudo : ")    # affiche la question, attend une ligne + Entrée
age_texte = input("Ton âge : ")    # toujours du TEXTE, même si tu tapes des chiffres
age = int(age_texte)               # conversion en nombre entier
print(f"Salut {pseudo}, l'an prochain tu auras {age + 1} ans")
```

Si tu tapes `Sam` puis `17`, tu vois :

```text
Ton pseudo : Sam
Ton âge : 17
Salut Sam, l'an prochain tu auras 18 ans
```

<Encadre type="piege">
`input` renvoie **toujours du texte**. Si tu tapes `abc` et que tu fais `int("abc")`, Python s'arrête avec `ValueError: invalid literal for int() with base 10: 'abc'`. En Lua, `tonumber` te rendait `nil` et le programme continuait ; en Python, il faudra **attraper** l'erreur avec `try` / `except` (module [D2](/parcours-d/d2-python-structures/)).
</Encadre>

## Étape 4 · Opérateurs et booléens (20 min)

Bonne nouvelle : presque tous les opérateurs que tu connais **existent à l'identique**.

| Opération | En Lua | En Python | Exemple Python et résultat |
|---|---|---|---|
| Calculs de base | `+ - *` | `+ - *` | `12 * 3` donne `36` |
| Division décimale | `/` | `/` | `10 / 4` donne `2.5` ; `10 / 2` donne `5.0` |
| Division entière | `//` | `//` | `17 // 5` donne `3` |
| Reste (modulo) | `%` | `%` | `17 % 5` donne `2` |
| Puissance | `^` | `**` | `2 ** 3` donne `8` (en Lua, `2 ^ 3` donne `8.0`) |
| Égal / différent | `==` / `~=` | `==` / `!=` | `3 != 4` donne `True` |
| Et / ou / non | `and` `or` `not` | `and` `or` `not` | identiques |
| Raccourci d'ajout | (n'existe pas) | `argent += 100` | équivaut à `argent = argent + 100` |
| Coller deux textes | `..` | `+` (deux `str` seulement) | `"Sam" + " Rivera"` |

Deux petits bonus de Python : `min`, `max` et `abs` existent sans rien importer (`max(3, 7)` donne `7`), et on peut **enchaîner** des comparaisons : `50 <= vitesse <= 130`, impossible en Lua.

### Le plus gros piège : ce qui est « faux »

<Encadre type="piege" titre="⚠️ En Python, 0 et le texte vide sont faux">
En Lua, **seuls `false` et `nil`** sont faux (B3). En Python, c'est plus large :

| Valeur | Dans un `if` en Lua | Dans un `if` en Python |
|---|---|---|
| `0` (et `0.0`) | vraie | **fausse** |
| `""` (texte vide) | vraie | **fausse** |
| liste ou dictionnaire vide | vraie | **fausse** |
| `None` / `nil` | fausse | fausse |
| `False` / `false` | fausse | fausse |

Conséquence directe : le truc `valeur or defaut` ne se comporte plus pareil. Avec `argent = 0`, Lua donne `0`, mais Python donne `100` pour `argent or 100` !
</Encadre>

Pour garder le comportement de Lua (« seulement si la valeur est absente »), on compare explicitement avec `None`, avec **`is None`** ou **`is not None`** (et pas `== None`). Et pour choisir une valeur en une ligne, Python a l'**expression conditionnelle** `valeur_si_vrai if condition else valeur_sinon` :

```python title="d1/defaut.py"
prime = 0
print(prime or 300)                             # 300 : le 0 est « faux », piège !
print(prime if prime is not None else 300)      # 0 : on teste seulement l'absence
```

### Texte et nombres ne se mélangent plus

En Lua, `"10" + 5` valait `15` (conversion automatique). En Python, mélanger texte et nombre **plante** :

```text
TypeError: can only concatenate str (not "int") to str
```

Il faut convertir toi-même (`str(5)`, `int("10")`) ou, mieux, utiliser une f-string.

## Étape 5 · Conditions et indentation (25 min)

C'est **la** grande différence visuelle. En Lua, `then` et `end` entourent un bloc. En Python, il n'y a ni `then` ni `end` : un bloc commence après un **deux-points** `:` et se reconnaît à son **retrait** (l'*indentation*) de **4 espaces**.

<Encadre type="analogie">
Pense à une liste à puces dans un document : les sous-points sont **décalés vers la droite**, et on sait qu'on a fini quand on revient à gauche. Python lit ton code comme ça : le décalage **fait partie du programme**.
</Encadre>

```python title="d1/permis.py"
age = 17
if age >= 18:
    print("Tu peux passer le permis")      # décalé de 4 espaces : dans le if
else:
    print("Encore", 18 - age, "an(s) à attendre")
print("Fin du contrôle")                    # pas décalé : toujours exécuté
```

```lua title="lua · le même programme"
local age = 17
if age >= 18 then
  print("Tu peux passer le permis")
else
  print("Encore " .. 18 - age .. " an(s) à attendre")
end
print("Fin du contrôle")
```

| En Lua | En Python |
|---|---|
| `if age >= 18 then` | `if age >= 18:` |
| `elseif sante >= 30 then` | `elif sante >= 30:` |
| `else` | `else:` |
| `end` | rien : on revient d'un niveau vers la gauche |

Trois règles :
1. une ligne `if`, `elif` ou `else` **finit par `:`** ;
2. toutes les lignes d'un même bloc ont **exactement le même retrait** (4 espaces, la règle de la PEP 8) ;
3. **jamais de mélange** tabulations et espaces. Dans VS Code, la touche **Tab** insère 4 espaces par défaut (d'après la documentation de VS Code) : tu n'as rien à régler.

```python title="d1/sante.py"
sante = 35
if sante >= 70:
    print("En forme")
elif sante >= 30:      # elif = « sinon si » (Lua : elseif)
    print("Blessé")
else:
    print("Critique")  # Blessé s'affiche : 35 >= 30, et le reste est ignoré
```

Comme en Lua, Python teste **dans l'ordre** et s'arrête au premier cas vrai : range tes cas du plus restrictif au plus large (module B3). Pas besoin de parenthèses autour de la condition, et `and`, `or`, `not` s'écrivent comme en Lua.

<Encadre type="astuce">
Un message d'erreur Python se lit **de bas en haut** : la **dernière ligne** dit *quoi* (`IndentationError: …`), la ligne `File "…", line 3` juste au-dessus dit *où*. Commence toujours par la dernière ligne.
</Encadre>

## Erreurs fréquentes

Messages copiés tels quels depuis une exécution réelle avec **Python 3.13** (les chemins et le détail du texte changent légèrement avec d'autres versions).

| Message | Cause | Solution |
|---|---|---|
| `IndentationError: expected an indented block after 'if' statement on line 2` | La ligne après `if …:` n'est pas décalée | Décale-la de 4 espaces |
| `IndentationError: unindent does not match any outer indentation level` | Une ligne revient à un retrait qui n'existe pas | Aligne-la exactement sous son `if` |
| `IndentationError: unexpected indent` | Une ligne est décalée sans raison | Retire les espaces en trop |
| `TabError: inconsistent use of tabs and spaces in indentation` | Tabulations et espaces mélangés | Utilise seulement des espaces |
| `SyntaxError: expected ':'` | `:` oublié à la fin de `if`, `else`, `def`… | Ajoute le `:` |
| `SyntaxError: invalid syntax` (flèche sous `elseif`) | Le `elseif` de Lua n'existe pas | Écris `elif` |
| `SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?` | `=` à la place de `==` dans un `if` | Utilise `==` pour comparer |
| `NameError: name 'true' is not defined. Did you mean: 'True'?` | `true`, `false` écrits à la Lua | `True`, `False`, `None` |
| `NameError: name 'argnet' is not defined. Did you mean: 'argent'?` | Faute de frappe dans un nom | Corrige l'orthographe |
| `TypeError: can only concatenate str (not "int") to str` | `+` entre un texte et un nombre | Utilise une f-string ou `str()` |
| `ValueError: invalid literal for int() with base 10: 'abc'` | `int()` sur un texte qui n'est pas un nombre | Vérifie la saisie (`try` / `except`, module D2) |
| `SyntaxError: Missing parentheses in call to 'print'. Did you mean print(...)?` | `print "texte"` sans parenthèses (vieux Python 2) | `print("texte")` |
| `python` n'est pas reconnu (Windows) | Terminal ouvert avant l'installation, ou Python absent | Ferme et rouvre le terminal, essaie `py --version`, sinon reprends l'étape 1 (message exact **non vérifié sur Windows**) |

<Exercice id="D1-ex03" titre="Traduire : le plein d'essence (Lua vers Python)" niveau="vert" dossier="D1/ex03" fichier="plein.py">
Voici un programme Lua. Écris le **même programme en Python** : il doit afficher exactement les quatre lignes attendues ci-dessous.

```lua title="plein.lua"
local argent = 130
local prix_plein = 40
local pleins = argent // prix_plein
local reste = argent % prix_plein
local nom = "Sam"
print(nom .. " peut faire " .. pleins .. " pleins")
print("Il lui reste " .. reste .. " €")
print("La moitié de son argent : " .. argent / 2)
print(#nom)
```

<div slot="indice1">Regarde ce qui change : le mot `local`, les `..`, le `#nom`. Les calculs `//`, `%` et `/` sont identiques.</div>
<div slot="indice2">Les `..` deviennent une f-string : `f"{nom} peut faire {pleins} pleins"`.</div>
<div slot="indice3">`#nom` devient `len(nom)`. Pas de `local` en Python.</div>
<div slot="solution">`65.0` s'affiche avec un `.0` dans les deux langages car `/` donne toujours un décimal. Aide-mémoire : `local` disparaît, `..` devient une f-string, `#x` devient `len(x)`, `--` devient `#`.</div>
</Exercice>

<Exercice id="D1-ex05" titre="Lecture : vrai ou faux ?" niveau="jaune" type="lecture" dossier="D1/ex05" fichier="vrai_ou_faux.py">

<div slot="indice3">`argent or 100` : `or` renvoie le premier élément « vrai ». Avec `argent = 0`, qui est faux, il passe au suivant.</div>

```python title="garage.py"

vehicules = 3
places = 14
age = 17
permis = False

if age >= 18 and permis:
    print("Kim peut conduire")
elif age >= 16 and not permis:
    print("Kim peut passer le permis")
else:
    print("Kim doit attendre")

    print(f"{places // vehicules} places par véhicule, reste {places % vehicules}")

```

## Récapitulatif

- Python : `python fichier.py`. Commentaire `#`. Pas de `local` : `x = 5`. Variables en `snake_case`.
- Types : `int`, `float`, `str`, `bool` (`True` / `False`), `None` ; `type()` donne le type. Aucune conversion automatique texte / nombre : `int()`, `float()`, `str()`.
- Afficher : `print(a, b)` sépare par une espace ; les **f-strings** `f"{nom} a {argent} €"` remplacent `..` et `string.format` (`:.2f` pour deux décimales). Lire : `input("…")` renvoie toujours du texte.
- Opérateurs identiques à Lua (`+ - * / // %`, `and or not`), sauf `**` (puissance), `!=` (différent), `+=`, et `len()` à la place de `#`.
- **Piège numéro 1** : `0`, `""` et les collections vides sont **faux** en Python (vrais en Lua) ; teste `is None` pour l'absence de valeur.
- Conditions : `if … :`, `elif … :`, `else:` ; le bloc est **retiré de 4 espaces**, sans `then` ni `end`.
- Une erreur Python se lit par la **dernière ligne** (le quoi) puis la ligne `line N` (le où).

## Je suis bloqué, que faire ?

1. **Relis l'erreur par le bas** : le type (`IndentationError`, `NameError`, `TypeError`…) puis le numéro de ligne.
2. **Isole** : copie les 5 lignes en cause dans un fichier à part, ou teste-les dans la console interactive (`python`).
3. **Compte tes espaces** : en cas d'`IndentationError`, regarde l'indentation affichée en bas à droite de VS Code ou active `editor.renderWhitespace` (voir le tutoriel d'installation).
4. **Compare avec Lua** : si ça marchait en Lua, cherche dans le tableau de l'étape correspondante ce qui change.
5. **Cherche dans la doc** : le [tutoriel officiel](https://docs.python.org/fr/3/tutorial/) est en français.
6. **Demande à une IA des indices, pas la solution.** Prompt modèle :

```text

Ne me donne PAS le code corrigé : explique-moi d'abord ce que dit le message,
puis donne-moi un indice pour que je trouve l'erreur moi-même.
```
