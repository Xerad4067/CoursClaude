**Pourquoi c'est utile ?** Sur un serveur roleplay, tout est **donnée** : le nom d'un joueur, son argent, son métier, s'il a le permis. Les variables sont les boîtes où l'on range ces données.

## Étape 1 · Une variable, c'est une boîte étiquetée (20 min)

<Encadre type="analogie">
Une **variable** est une **boîte avec une étiquette**. L'étiquette est le **nom** (`argent`), le contenu est la **valeur** (`1500`). Tu peux regarder dans la boîte, ou remplacer son contenu.
</Encadre>

```lua title="b1/variables.lua"
local nom = "Sam"      -- une boîte « nom » qui contient le texte Sam
local argent = 1500    -- une boîte « argent » qui contient le nombre 1500
print(nom)
print(argent)
```

Ligne par ligne :
- `local` : on **crée** une nouvelle variable (on verra au module B5 pourquoi `local` est important ; prends l'habitude de toujours l'écrire) ;
- `nom` : son nom ;
- `=` : « reçoit » (ce n'est **pas** « est égal à » des maths) ;
- `"Sam"` : la valeur rangée dedans.

`print(nom)` affiche **le contenu** de la boîte : `Sam`. Attention : `print("nom")` afficherait le **texte** `nom`.

## Étape 2 · Changer le contenu (20 min)

```lua title="b1/salaire.lua"
local argent = 1500
argent = argent + 200   -- on calcule 1500 + 200, puis on range 1700 dans argent
argent = argent - 50    -- 1700 - 50 = 1650
print(argent)           --> 1650
```

`argent = argent + 200` se lit **de droite à gauche** : Lua calcule d'abord `argent + 200` avec l'ancienne valeur, puis range le résultat dans `argent`. Pas de `local` ici : la boîte existe déjà, on change seulement son contenu.

<Encadre type="piege">
Écrire `local argent = ...` une deuxième fois crée une **nouvelle** boîte qui cache l'ancienne. Pour modifier une variable existante : son nom, `=`, la nouvelle valeur, sans `local`.
</Encadre>

## Étape 3 · Les types (25 min)

Chaque valeur a un **type** (sa nature). La fonction `type()` le donne :

| Type | Exemples | Utilisation RP |
|---|---|---|
| `number` (nombre) | `1500`, `3.5`, `-20` | argent, santé, vitesse |
| `string` (chaîne) | `"Sam"`, `"taxi"`, `""` | noms, métiers, messages |
| `boolean` (booléen) | `true`, `false` | a le permis ? est admin ? |
| `nil` (rien) | `nil` | « pas de valeur » |

```lua title="b1/types.lua"
print(type(1500))    --> number
print(type("taxi"))  --> string
print(type(true))    --> boolean
print(type(nil))     --> nil
```

Lua 5.4 distingue deux sortes de nombres : les **entiers** (`integer`, comme `42`) et les **décimaux** (`float`, comme `42.0` ou `3.5`). `type()` dit `number` pour les deux ; `math.type()` précise lequel. La division `/` donne **toujours** un décimal : `10 / 2` vaut `5.0`.

<Encadre type="retenir">
`"42"` (avec guillemets) est une **chaîne**, `42` est un **nombre**. Pour Lua, ce sont deux choses différentes.
</Encadre>

## Étape 4 · nil, fautes de frappe et noms clairs (25 min)

`nil` signifie **« rien »**. Une variable qui n'a jamais reçu de valeur vaut `nil`. Et une **faute de frappe** dans un nom de variable ne provoque pas toujours d'erreur :

```lua title="b1/faute.lua"
local argent = 100
print(argnet)   --> nil (Lua cherche une variable « argnet » qui n'existe pas)
```

Lua n'a pas planté : il a affiché `nil`. C'est un **bug silencieux**. L'extension Lua de VS Code souligne heureusement ce genre de nom inconnu.

Si tu **calcules** avec une variable vide, là Lua s'arrête :

```text
lua: faute.lua:3: attempt to perform arithmetic on a nil value (global 'argnet')
```

### Bien nommer
- Des noms qui disent **ce que contient** la boîte : `argent`, `metierActuel`, `aLePermis`.
- Une convention : ce cours utilise le **camelCase** (`prixTotal`) ; Nanos World écrit souvent ses exemples en *snake_case* (`prop_table`). Choisis-en une et reste cohérent dans un fichier.
- Pas d'accents, pas d'espaces, ne commence pas par un chiffre (`1joueur` est interdit).
- Évite `a`, `x`, `truc` : dans trois semaines, tu ne sauras plus ce qu'il y a dedans.

<FinEtape id="B1-e4" titre="nil et noms clairs" victoire="tu sais pourquoi une faute de frappe peut donner nil, et tu choisis des noms clairs." prochaine="les exercices 1 à 4." />

## Erreurs fréquentes

| Message ou symptôme | Cause | Solution |
|---|---|---|
| `nil` affiché au lieu de la valeur | Faute de frappe dans le nom | Compare les noms lettre par lettre |
| `attempt to perform arithmetic on a nil value (global 'x')` | Calcul avec une variable vide ou mal nommée | Vérifie qu'elle a reçu une valeur avant |
| `malformed number near '1x'` | Nom qui commence par un chiffre | Commence par une lettre : `joueur1` |
| `nom` affiché au lieu de `Sam` | Guillemets autour du nom de variable | `print(nom)` sans guillemets |

## Récapitulatif

- `local nom = valeur` crée une variable ; `nom = nouvelleValeur` la modifie.
- Types : `number` (entier ou décimal), `string`, `boolean`, `nil` ; `type()` les donne.
- `nil` = rien ; une faute de frappe dans un nom donne souvent `nil` sans erreur.
- Des noms clairs, une convention, pas d'accents.
