**Pourquoi c'est utile ?** Un vrai serveur a **des centaines de lignes** : il faut les ranger en **plusieurs fichiers** (modules). Et Nanos World appelle tes fonctions quand un événement survient : tu lui **passes des fonctions en paramètre** en permanence.

## Étape 1 · Tables dans des tables (20 min)

```lua title="b7/serveur.lua"
local serveur = {
  nom = "RP Horizon",
  joueurs = {
    { nom = "Sam", argent = 1500 },
    { nom = "Kim", argent = 900 },
  },
}
print(serveur.joueurs[2].nom)   --> Kim : on descend niveau par niveau
for _, j in ipairs(serveur.joueurs) do
  print(j.nom, j.argent)
end
```

Lis `serveur.joueurs[2].nom` de gauche à droite : dans `serveur`, la clé `joueurs` (une liste), son 2e élément (une fiche), sa clé `nom`.

## Étape 2 · Les fonctions sont des valeurs (20 min)

En Lua, une fonction se range dans une variable ou une table, et se passe en paramètre :

```lua title="b7/commandes.lua"
local commandes = {
  aide = function() print("Commandes : /aide, /argent") end,
  argent = function() print("Tu as 1500 €") end,
}
local tapee = "aide"
commandes[tapee]()          -- appelle la fonction rangée sous la clé "aide"
```

C'est exactement le principe des **événements** de Nanos World : tu donnes au jeu une fonction, il l'appelle au bon moment.

```lua title="b7/trier.lua"
local joueurs = { { nom = "Sam", argent = 1500 }, { nom = "Kim", argent = 2200 } }
-- table.sort accepte une fonction qui dit si a doit passer avant b
table.sort(joueurs, function(a, b) return a.argent > b.argent end)
print(joueurs[1].nom)       --> Kim (le plus riche en premier)
```

## Étape 3 · Les closures (25 min)

Une **closure** (fermeture) est une fonction qui **se souvient** des variables locales qui existaient autour d'elle quand elle a été créée, même après.

```lua title="b7/compteur.lua"
local function creerCompteur()
  local n = 0                  -- variable locale de creerCompteur
  return function()            -- cette fonction « emporte » n avec elle
    n = n + 1
    return n
  end
end
local suivant = creerCompteur()
print(suivant(), suivant())    --> 1   2
```

<Encadre type="analogie">
Une closure, c'est un **sac à dos** : la fonction part avec ses variables. Personne d'autre ne peut fouiller dedans : c'est une façon de **protéger** une donnée (un solde, un compteur de tickets).
</Encadre>

## Étape 4 · Les modules avec require (25 min)

Un **module** est un fichier Lua qui **renvoie une table** de fonctions et de données.

```lua title="b7/outils.lua"
local outils = {}

function outils.pourcentage(valeur, taux)
  return valeur * taux // 100
end

return outils                  -- indispensable : c'est ce que require reçoit
```

```lua title="b7/main.lua"
local outils = require("outils")   -- charge outils.lua (dans le même dossier)
print(outils.pourcentage(200, 15)) --> 30
```

Lance `lua main.lua` **depuis le dossier** qui contient les deux fichiers : `require("outils")` cherche `outils.lua` dans le dossier courant. Un module n'est chargé qu'**une fois** : les `require` suivants renvoient la même table.

<Encadre type="retenir" titre="📌 Et dans Nanos World ?">
Nanos World a son propre mécanisme pour charger un autre fichier d'un package, `Package.Require` (vu au parcours E). Le principe est le même : découper par responsabilité (argent, métiers, inventaire…).
</Encadre>

## Erreurs fréquentes

| Message | Cause | Solution |
|---|---|---|
| `attempt to index a nil value (field 'joueur')` | Clé mal écrite dans un chemin `a.b.c` | Vérifie chaque niveau (`print(serveur.joueur)`) |
| `module 'outils' not found` | Fichier absent du dossier courant, ou mauvais nom | `dir`, puis lance `lua` depuis le bon dossier |
| `attempt to index a boolean value (local 'outils')` | Le module n'a pas de `return` à la fin | Ajoute `return outils` |
| `attempt to call a nil value (field 'pourcentag')` | Nom de fonction mal écrit dans le module | Compare les noms |

Crée un module `outils.lua` avec deux fonctions : `pourcentage(valeur, taux)` et `formaterArgent(montant)` (celle du défi B5). Dans `main.lua`, charge-le avec `require` et produis l'affichage attendu.

<div slot="indice1">Le module commence par `local outils = {}` et finit par `return outils`.</div>
<div slot="indice2">Définis les fonctions avec `function outils.nom(...)`.</div>
<div slot="indice3">Dans `main.lua` : `local outils = require("outils")`, puis `outils.formaterArgent(...)`.</div>
<div slot="solution">

Le module `outils.lua` (testé avec la solution) :
```lua title="outils.lua"
local outils = {}

function outils.pourcentage(valeur, taux)
  return valeur * taux // 100
end

function outils.formaterArgent(montant)
  local texte = tostring(montant)
  local resultat = ""
  local compteur = 0
  for i = #texte, 1, -1 do
    resultat = string.sub(texte, i, i) .. resultat
    compteur = compteur + 1
    if compteur % 3 == 0 and i > 1 then
      resultat = " " .. resultat
    end
  end
  return resultat .. " €"
end

return outils
```

<div slot="validation">Le programme principal ne contient aucune donnée de métier : tout vient du module.</div>
<div slot="indice1">Dans le module, la liste est une variable `local` : seules les fonctions sont exposées.</div>
<div slot="indice2">`trouver` parcourt la liste et compare `fiche.nom == nom`.</div>
<div slot="indice3">Si rien n'est trouvé, `return nil` (ou rien) : le programme principal teste `if fiche then … else … end`.</div>
<div slot="solution">

Le module `metiers.lua` (testé avec la solution) :
```lua title="metiers.lua"
local metiers = {}

-- Données privées du module : invisibles depuis main.lua.
local liste = {
  { nom = "taxi", salaireHoraire = 12, vehicule = "Taxi" },
  { nom = "mecanicien", salaireHoraire = 14, vehicule = "Dépanneuse" },
  { nom = "livreur", salaireHoraire = 11, vehicule = "Camionnette" },
}

function metiers.lister()
  return liste
end

function metiers.trouver(nom)
  for _, fiche in ipairs(liste) do
    if fiche.nom == nom then
      return fiche
    end
  end
  return nil
end

return metiers
```
Ce module deviendra une brique de ton serveur RP : le jour où tu ajoutes un métier, tu ne touches qu'à ce fichier.

## Récapitulatif

- Tables imbriquées : `a.b[2].c`, on descend niveau par niveau.
- Fonctions = valeurs : dans des tables, en paramètre (callbacks), anonymes.
- Closure : fonction + ses variables locales d'origine ; utile pour protéger une donnée.
- Module : fichier qui `return` une table ; `local m = require("nom")`.

## Je suis bloqué, que faire ?

Pour un chemin qui plante, affiche chaque niveau : `print(serveur)`, `print(serveur.joueurs)`, `print(serveur.joueurs[1])`. Pour un module : vérifie le `return` final et le dossier courant (`pwd`, `dir`).
