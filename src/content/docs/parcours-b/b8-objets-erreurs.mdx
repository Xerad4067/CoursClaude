**Pourquoi c'est utile ?** Les classes de Nanos World (`Player`, `Character`, `Vehicle`…) s'utilisent avec des **méthodes** (`player:GetName()`). Un serveur doit aussi **survivre aux erreurs** (une commande mal tapée ne doit pas tout faire planter) et **analyser du texte** (les commandes du chat).

## Étape 1 · Méthodes, `:` et self (20 min)

```lua title="b8/compte.lua"
local compte = { solde = 100 }

function compte:deposer(montant)     -- le : ajoute un paramètre caché : self
  self.solde = self.solde + montant  -- self = la table sur laquelle on appelle
end

compte:deposer(50)                   -- équivaut à compte.deposer(compte, 50)
print(compte.solde)                  --> 150
```

`compte:deposer(50)` est un raccourci pour `compte.deposer(compte, 50)` : la table est passée automatiquement comme premier argument, nommé `self`.

## Étape 2 · Une classe simple avec les métatables (25 min)

Une **métatable** change le comportement d'une table. Avec la clé spéciale `__index`, si une clé est absente d'une table, Lua va la chercher **ailleurs** : c'est ainsi qu'on partage des méthodes entre plusieurs objets.

```lua title="b8/vehicule.lua"
local Vehicule = {}
Vehicule.__index = Vehicule          -- « si une clé manque, cherche dans Vehicule »

function Vehicule.nouveau(nom, vitesse)
  local v = setmetatable({}, Vehicule)   -- v utilise Vehicule comme métatable
  v.nom = nom
  v.vitesse = vitesse
  return v
end

function Vehicule:decrire()
  return self.nom .. " roule à " .. self.vitesse .. " km/h"
end

local taxi = Vehicule.nouveau("Taxi", 120)
print(taxi:decrire())                --> Taxi roule à 120 km/h
```

<Encadre type="analogie">
`Vehicule` est le **plan** (la classe) ; `taxi` est **une voiture construite** avec ce plan (un objet, une *instance*). La voiture n'a pas de copie du mode d'emploi : quand elle en a besoin, elle consulte le plan grâce à `__index`. Au parcours D, tu retrouveras ces notions (classe, objet, méthode) en programmation orientée objet.
</Encadre>

## Étape 3 · error et pcall (20 min)

`error(message)` **lève** une erreur : le programme s'arrête… sauf si on l'appelle via `pcall` (*protected call*), qui l'**attrape**.

```lua title="b8/retrait.lua"
local function retirer(solde, montant)
  if montant > solde then
    error("Solde insuffisant", 0)    -- 0 : message sans numéro de ligne
  end
  return solde - montant
end

local ok, resultat = pcall(retirer, 100, 500)
print(ok, resultat)                  --> false   Solde insuffisant
```

`pcall(f, arg1, arg2)` renvoie `true` + les résultats si tout va bien, ou `false` + le message d'erreur. Le second argument de `error` (le **niveau**) : sans lui, Lua ajoute le fichier et la ligne au message ; avec `0`, le message reste tel quel (pratique pour l'afficher au joueur).

## Étape 4 · Motifs de chaînes et sérialisation (25 min)

Les **motifs** (*patterns*) de Lua décrivent la forme d'un texte : `%a` une lettre, `%d` un chiffre, `%s` un espace, `+` « un ou plusieurs », `*` « zéro ou plusieurs », `^` début, `$` fin, et les parenthèses **capturent**.

```lua title="b8/commande.lua"
local message = "/donner Sam 250"
local cmd, cible, montant = string.match(message, "^/(%a+) (%a+) (%d+)$")
print(cmd, cible, montant)           --> donner   Sam   250
print(string.find("Bienvenue au garage", "garage"))   --> 14   19
print(string.gsub("bonjour", "o", "0"))               --> b0nj0ur   2
```

**Sérialiser**, c'est transformer une table en **texte** pour la sauvegarder (fichier, base de données) ; **désérialiser**, c'est l'inverse. Pour une table simple, on peut produire du code Lua et le recharger avec `load` (à réserver à **tes** données : ne charge jamais du texte venant d'un joueur, il pourrait contenir du code). Le format standard d'échange sur le web est le **JSON** ; Nanos World propose ses propres outils de sauvegarde, vus au parcours E.

<Encadre type="piege" titre="⚠️ Sécurité">
`load` exécute du code. Ne l'utilise jamais sur une chaîne fournie par un joueur ou téléchargée : c'est une faille. Pour des données externes, utilise un format de données (JSON) et un lecteur dédié.
</Encadre>

## Erreurs fréquentes

| Message | Cause | Solution |
|---|---|---|
| `attempt to index a number value (local 'self')` | Méthode appelée avec `.` au lieu de `:` | `objet:methode(...)` |
| `attempt to call a nil value (method 'decrir')` | Méthode inexistante (faute, ou `__index` oublié) | Vérifie le nom et `Classe.__index = Classe` |
| `string.match` renvoie `nil` | Le texte ne correspond pas au motif | Teste le motif sur un exemple simple |
| Programme arrêté par une erreur prévue | `error` appelé hors `pcall` | Appelle la fonction risquée via `pcall` |

## Récapitulatif

- Méthodes : `function T:m() … self … end`, appel `obj:m()`.
- Classe : `C.__index = C`, `setmetatable({}, C)` dans un constructeur.
- Erreurs : `error(msg, 0)` pour lever, `pcall(f, ...)` pour attraper.
- Texte : `string.match`, `find`, `gsub` avec motifs (`%a %d %s + * ^ $` et captures).
- Sérialiser : table → texte ; `load` seulement pour tes propres données.

## Je suis bloqué, que faire ?

Pour un motif, teste-le dans un fichier à part sur une seule phrase et affiche le résultat de `string.match`. Pour une classe, vérifie dans l'ordre : `__index`, `setmetatable`, le `:` à la définition **et** à l'appel.
