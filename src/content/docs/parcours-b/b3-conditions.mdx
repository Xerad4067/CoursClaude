## Étape 1 · if, else (20 min)

<Encadre type="analogie">
Une condition, c'est le **videur** d'une boîte de nuit : « **si** tu as 18 ans ou plus, **alors** tu entres, **sinon** tu rentres chez toi ».
</Encadre>

```lua title="b3/permis.lua"
local age = 17
if age >= 18 then
  print("Tu peux passer le permis")
else
  print("Encore " .. 18 - age .. " an(s) à attendre")
end
```

- `if condition then` : si la condition est vraie, on exécute le bloc qui suit ;
- `else` : sinon, on exécute l'autre bloc ;
- `end` : fin du `if` (obligatoire !).

Le code à l'intérieur est **indenté** (décalé de 2 espaces) : Lua s'en moque, mais toi, tu vois tout de suite ce qui dépend de quoi.

## Étape 2 · elseif : plusieurs cas (20 min)

```lua title="b3/sante.lua"
local sante = 35
if sante >= 70 then
  print("En forme")
elseif sante >= 30 then
  print("Blessé")
else
  print("Critique")
end
```

Lua teste **dans l'ordre** et s'arrête au **premier** cas vrai. Ici `35 >= 70` est faux, `35 >= 30` est vrai → `Blessé`, et le reste est ignoré.

<Encadre type="piege">
L'ordre compte : si tu testes `sante >= 30` **avant** `sante >= 70`, un joueur à 90 sera classé « Blessé ». Range les cas du plus restrictif au plus large.
</Encadre>

## Étape 3 · and, or, not (20 min)

| Opérateur | Vrai si… | Exemple RP |
|---|---|---|
| `a and b` | les deux sont vrais | assez d'argent **et** le permis |
| `a or b` | au moins un est vrai | admin **ou** modérateur |
| `not a` | `a` est faux | **pas** banni |

```lua title="b3/acces.lua"
local estAdmin, estModo = false, true
if estAdmin or estModo then
  print("Accès au panneau de modération")
end
```

## Étape 4 · Vrai, faux… et les surprises de Lua (20 min)

En Lua, **seuls `false` et `nil` sont faux**. Tout le reste est vrai, **y compris `0` et la chaîne vide `""`** (différent d'autres langages).

Conséquence pratique : `or` donne une **valeur par défaut**.

```lua title="b3/defaut.lua"
local saisie = "abc"
local montant = tonumber(saisie) or 0   -- tonumber renvoie nil, donc on prend 0
print(montant)                          --> 0
```

`a or b` vaut `a` si `a` est vrai, sinon `b`. Et `a and b` vaut `a` si `a` est faux, sinon `b`.

<Encadre type="retenir">
Vérifie toujours une saisie : `local n = tonumber(texte)`, puis `if n == nil then ... end`. Sur un serveur, **toute donnée venant d'un joueur est suspecte**.
</Encadre>

<FinEtape id="B3-e4" titre="Vrai et faux en Lua" victoire="tu sais que 0 est vrai en Lua et tu utilises or pour une valeur par défaut." prochaine="les exercices, puis le contrôle d'achat de véhicule." />

## Erreurs fréquentes

| Message | Cause | Solution |
|---|---|---|
| `'then' expected near '='` | `=` au lieu de `==` dans la condition | Comparer, c'est `==` |
| `'end' expected (to close 'if' at line 3) near <eof>` | `end` oublié | Un `end` par `if` (pas par `elseif`) |
| `'then' expected near 'print'` | `then` oublié | `if condition then` |
| Un cas n'est jamais atteint | Mauvais ordre des `elseif` | Du plus restrictif au plus large |

## Récapitulatif

- `if … then … elseif … then … else … end` ; Lua s'arrête au premier cas vrai.
- `and`, `or`, `not` ; seuls `false` et `nil` sont faux ; `x or valeurParDefaut`.
- Comparer = `==` ; toujours valider les saisies (`tonumber` puis test de `nil`).

## Je suis bloqué, que faire ?

Ajoute un `print` **avant** le `if` pour voir les valeurs réelles testées (`print("age =", age)`). Vérifie ensuite chaque condition à voix haute.
